01
Text hashing
SHA digests convert arbitrary text to a fixed-length, deterministic digest. The same input gives the same digest; this is useful for integrity checks, not password storage.
02
Password hashing
bcrypt, Argon2id, and PBKDF2 use a salt and configurable work to make password guesses expensive. SHA-256 of a password is not a substitute for a password hashing function.
03
Educational algorithms
MD5 and SHA-1 are provided for compatibility and learning only. Do not use them for security-sensitive applications. Hashes are not designed to be decrypted.

02 — COMPARE
Hash Types
Different algorithms solve different problems. Password storage needs deliberately expensive, salted functions.
⚠
Fast hashes are not password storage
MD5 and SHA-1 are broken for many security uses; SHA-256 and SHA-512 are fast. Do not use these alone for password storage. Prefer Argon2id, bcrypt, or appropriately configured PBKDF2.

04 — VERIFY SAFELY
Password Verification
Check a candidate password against its stored hash with the password API. Never compare newly generated hash strings.
SAFE DEMONSTRATION
   verify-password.php
<?php
// Set both values from trusted application inputs/storage.
$password = $submittedPassword;
$storedHash = $user['password'];

if (password_verify($submittedPassword, $hash)) {
    echo "Password matches";
} else {
    echo "Invalid credentials";
}
?>
PASSWORD_DEFAULT selects a password hashing algorithm; do not replace it with SHA-256.
01
Hash once, store safely
PHP's password_hash() generates a salt and embeds the algorithm parameters in the result.
02
Verify the candidate
password_verify($candidate, $storedHash) checks the submitted candidate against the saved hash.
03
Let the API handle salt
Bcrypt hashes contain their salt. Do not generate another hash and compare strings; verify against the stored value.
This is an educational pattern. Initialize $password and $submittedPassword appropriately, and load the stored hash from the account record.

      
05 — BUILD GOOD HABITS
Security Best Practices
A hash format is only one part of a safe password system.
01
Use a password hashing API
Choose Argon2id, bcrypt, or tuned PBKDF2 with a maintained platform library.
02
Keep work factors current
Set parameters based on your platform and hardware, then review them over time.
03
Never store plaintext
Seed and application flows should store password hashes, not reusable passwords.
04
Use parameterized SQL
Bind application values as parameters. Avoid building SQL by concatenating input.
