## Confirmed findings and fixes

- **High ? public web-root exposure:** before the fix, Apache returned HTTP 200 for `/.env`, `/read%20me%20.txt/sql.txt`, the dataset CSV, and `/ml/models/latest.json`. Added root and directory access rules; the same checks now return HTTP 403. The response bodies were not read.
- **High ? clinician vitals authorization:** added approved-doctor and appointment relationship checks to the vitals endpoint; unauthenticated requests return 401. An authorized patient request was not exercised.
- **High ? mixed-role sessions:** successful sign-ins clear other role IDs and regenerate the session; both sign-out routes clear the complete session. Valid role-to-role authentication was inspected but not exercised with a real account.
- **High ? public PHI exports:** exports are allowlisted, admin-session-only streamed responses; no CSV is written under the web root. Exporting with an authenticated administrator was not exercised.
- **High ? sensor target fallback:** sensor ingestion now requires an explicit server-side patient mapping and valid device token; no fake default patient or generated vital inserts remain.
- **High ? ESP32 temperature conversion:** corrected Kelvin-to-Celsius offset from 263.15 to 273.15. Hardware validation remains outstanding.
- **Medium ? appointment enum mismatch:** doctor status options now match the live enum (`pending`, `completed`, `cancelled`).
- **Medium ? unvalidated anomaly score/alert:** removed the arbitrary score and alert sound from the Isolation Forest page; latest incomplete/non-finite readings now produce an unavailable/insufficient-data state.
- **Medium ? schema width validation:** registration and profile inputs align to the inspected MySQL column widths; read-only schema inspection confirmed the account, vital, appointment, prescription, suggestion, OTP and prediction columns and foreign keys.
- **Medium ? Docker build context:** excludes local Python environments and generated/offline data from Docker context.
- **Low ? tied reading timestamps:** patient/doctor latest readings and history use `recorded_at` plus `id` for deterministic ordering.
- **Low ? unnecessary credential fields:** profile/dashboard queries no longer select password hashes.
- **Medium ? patient deletion OTP residue:** patient deletion now removes associated reset-code rows in its transaction; deletion itself was not run.

## Remaining audit risks and limitations

- Login and OTP request throttling is session-based or absent, so a new session can bypass it. Add server-wide/IP-aware throttling before exposing authentication publicly.
- The ESP32 example uses plain HTTP; use HTTPS on any untrusted network. No real device request was sent.
- Doctor authorization currently treats an appointment row as the relationship, including historical/cancelled rows; confirm whether cancellation should revoke vitals access.
- `patient_suggestions` exists in MySQL but has no patient/doctor dashboard workflow in the inspected UI.
- The valid login, registration insert, appointment booking, prescription CRUD, patient deletion, SMS, Gemini, and live ML/RAG operations were not run to avoid writing accounts/records, deleting data, or calling external services.
- No graphical browser/responsive screenshot verification succeeded. CSS/markup behavior was inspected; visual regression and actual mobile interaction remain unverified.
- The source review is incomplete; see Not reviewed and In progress rows. Do not treat this report as a complete production-readiness certification.
