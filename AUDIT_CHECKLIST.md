The doctor dashboard uses the same scope for patient and latest-vitals queries (`doctor-dashboard.php:164-217`, `:262-278`).
- **Medium — endpoint error disclosure:** `get_patient_metrics.php` previously returned arbitrary exception text. Its handler now uses allowlisted status messages and logs unexpected/database failures server-side (`get_patient_metrics.php:58-78`).
- **High — role switching/session persistence:** successful doctor, patient, and administrator sign-in rotates the session ID and removes other role keys; sign-out clears the full session (`doctor/login_doctor.php:24-40`, `patient/login_patient.php:24-44`, `admin-login.php:20-34`, `logout.php:1-13`, `admin-logout.php:1-6`, `includes/session.php:1-23`). - **High — public PHI exports:** exports are allowlisted, administrator-session-only streamed responses with spreadsheet formula mitigation; no CSV is written under the web root (`export-data.php:1-81`).
- **High — sensor ingestion target:** `save_data.php` requires a configured device token and explicit server-side patient mapping; there is no generated-patient fallback. It validates sensor values before persistence (`save_data.php:1-77`).
- **High — patient record ownership:** patient dashboard/history and write paths bind operations to the authenticated patient ID (`patient-dashboard.php:79-100`, `add-health.php:1-156`, `book_appointment.php:1-61`, `download_prescription.php:1-74`).

- **Medium — prediction presentation:** removed an arbitrary anomaly score and alert sound; the experimental screen rejects incomplete/non-finite latest readings and distinguishes estimates from recorded values (`ml/predict_health.py:1-102`, `patient-prediction.php:1-232`).
- **Medium — dashboard blank/centering conflict:** the old global body layout could center content pages and dashboard shells incorrectly. Shared body resets and responsive page styles now use normal document flow (`css/app-ui.css:47-60`, `:193-200`, `css/dashboard-modern.css:19-38`). Visual verification remains incomplete.
- **Medium — schema/business-rule mismatches:** registration/profile input sizes match inspected MySQL widths; appointment status controls match `pending`, `completed`, and `cancelled`; deterministic health reading order uses timestamp plus ID. Schema inspection was read-only.
